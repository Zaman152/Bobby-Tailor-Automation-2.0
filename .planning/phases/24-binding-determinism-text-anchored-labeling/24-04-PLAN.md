<objective>
Establish the phase's central contract: **a raw candidate ID is never a line item.** A measured
quantity whose object identity is unknown is published to an unnamed-geometry ledger with its
evidence, and excluded from `calculated_takeoff` and `takeoff_summary`.

Purpose: three loci in `fusion.py` do `name = <label> or <candidate_id>` — `:1255` (symbols),
`:1633` (wall classes), `:2806` (rooms). All three correctly set `needs_review=True` with a
reason, so the flagging is honest; the raw ID then flows unmodified into
`calculated_takeoff[].description` and `takeoff_summary[].item`, so identifiers and a gridline
bubble named with a single digit reach the client report as line items. Phase 23 established
"a blank is never a zero"; the Phase 24 analogue is this one.

**Measured targets, resolved FREE this session — these are addresses, not hypotheses.**

| target | what it is | today |
|---|---|---|
| Crow page 0 room candidate 2 | label `4`, `label_source` is `text_in_polygon`, area 905.4 pt-squared at fpp 0.5556 | publishes as a line item named with a single digit at ~279.5 SF |
| Crow page 0 room candidate 1 | a 20-token label beginning with a door count and ending in a street name, `label_source` is `text_in_polygon`, area 1,283,231.5 pt-squared | publishes as a line item at ~396,053 SF |
| Crow symbol groups, all four sheets | 107 groups; **81 carry no contained text at all** | all 81 fall to the identifier fallback |
| Crow page 0 / 1 / 2 room candidates | 4 / 153 / 1 unlabeled | all fall to the identifier fallback |

Two further measured facts shape the gate:

1. The existing `_is_noise_token` (fusion.py:1093) **already returns True for a bare digit**.
   The predicate is not missing — it is simply never applied on the room path, where no noise
   gate exists at all. So the single-digit room name is closed by APPLYING an existing
   predicate, not by writing a new one.
2. The 20-token label is **not** caught by that predicate (it contains real words). It needs a
   second, structural rule. Its text was harvested from a schedule table that
   `tag_pairing.sheet_mask_rects` already knows how to mask.

**The scope fence, and the expected direction of the score.** Phase 25 owns making these
candidates detectable and nameable. Phase 24 owns only the contract that an unnamed one does
not publish. **Expect the naive accuracy metric to DROP when this lands** — the coincidental
high-count symbol hit stops looking like a column hit, and roughly two dozen identifier rows
leave the take-off. That is the correct, documented outcome and the same precedent Phase 23's
rails set. It is not a regression and must not be reversed by relaxing the gate.

**The 56 and the 136 are not to be touched.** Ground truth section 11.0 proved the 56-mark
cluster is 56 genuinely distinct marks and section 10 proved the 136 sit at a single Y —
collinear dimension ticks. Both apparent golden hits are coincidences. This plan's only
obligation to them is that each carries ONE deterministic outcome across runs: a text-anchored
name, or a ledger record. Never a count adjustment.

Output: a name-worthiness gate at all three leak sites, a room name-plausibility rule, and an
`unnamed_geometry` key on the fusion result carrying every excluded candidate with its evidence.
</objective>
