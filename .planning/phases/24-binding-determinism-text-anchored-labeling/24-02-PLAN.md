<objective>
Invert the wall-class naming precedence so deterministic evidence outranks the stochastic
vision label, and record every disagreement instead of discarding one side.

Purpose: V4-DET-02 is a precedence inversion, not new logic. `map_wall_classes_from_library`
(fusion.py:1375-1482) is already a complete zero-API classifier — printed-thickness match
within `_WALL_THICKNESS_TOL_IN = 1.5` marked `confident=True`, plus the location guard that
forbids a masonry object from binding the dominant-LF perimeter class (fusion.py:1394-1412,
whose comment records the reasoning: Crow's interior pump-room CMU wall is ~61 LF while the
perimeter tilt-up class is thousands). That classifier sits in the `elif` branch BEHIND the
vision label at fusion.py:1536-1543. The thickness-and-location rule V4-DET-02 asks for is
already written; it is simply demoted.

**Scope fence, stated up front.** This plan makes the wall bind invariant *given its object
list*. It cannot make it invariant *end to end*, because `map_wall_classes_from_library`'s
third argument comes from `_wall_objects_from_vocabulary(vocabulary)` (fusion.py:1361) and
that vocabulary is re-derived from the API on every run — defect F3, where run 1 produced
`Metal Downspout` and `Aluminum Storefront` while run 2 produced `Metal Downspouts` and
`Aluminum Storefront/Curtain Wall`. Plan 24-03 folds the name form and plan 24-05 stabilises
the object list. All three are required before V4-DET-02 holds end to end; this plan is the
one that makes the *decision* deterministic and is verifiable on its own.

**Explicitly out of scope:** the 8 vs 11,294 SF wall-area *values*. Those are measurement
outcomes. Phase 24 owns which class is called CMU, not what CMU measures.

Output: an inverted precedence block, a disagreement audit record, and four named tests
including the label-invariance differential that makes the flip structurally impossible
rather than merely unobserved.
</objective>
