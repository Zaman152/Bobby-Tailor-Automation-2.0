<objective>
Build the determinism harness — as the differential that actually detects the bug, not as the
requirement's literal words.

**The trap, and why the literal wording must not be implemented.** V4-DET-05 says "same fixture
N times asserts identical line items." `ReplayAnalyzer.__call__` (tests/replay_analyzer.py:160-233)
resolves a SHA256 over `(model, pass_type, prompt_text, image_count)` and returns the file's
response verbatim. It is a **pure function of the key**. Running the same fixture N times is
therefore identical *by construction* and would detect none of defects F1 through F9. Writing
the requirement's literal words as the test would produce a gate that passes for having looked
at nothing — precisely the failure `tests/test_phase23_acceptance.py`'s rule 3 forbids.

**The harness that does detect it:**

> Hold the geometry fixed. VARY the model's answers within schema-legal bounds. Assert the
> published line-item set is invariant.

Two fixture sets: variant A carries the labels observed in the 14:19 run, variant B the labels
observed in the 18:13 run. Both run against the same PDF and the same deterministic geometry.
The gate asserts the published item set is equal. That is the exact bug class the phase exists
to kill: one candidate publishing as one name in one run and a different name in the next.

**Feasibility, established and not assumed.** The saved runs contain no raw API responses — every
top-level key of both files was enumerated and none holds one. But the fixtures can still be
authored for FREE, because two things are true:

1. **The replay key is computable offline.** It depends on `_resolve_model` (environment-driven,
   pinned by conftest), `_build_user_message` (a pure string function), the pass type and the
   image count. None needs a credential. The deterministic half of the pipeline runs with zero
   API — `scripts/geom_probe.py` and `scripts/fusion_probe.py` already do exactly that — so a
   script can compute every key it needs.
2. **Both runs' per-candidate labels are recoverable from their fused output.** The wall-class
   labels are reconstructable from the wall component names plus their name source; the symbol
   matches from which candidates carry a real name versus a raw identifier; the vocabulary
   pass's object list from the expected-but-not-measured rows plus the library-sourced rows.

Assumption A2 rates that recoverability MEDIUM — it was reasoned from field presence, not proven
by writing the reconstruction. This plan proves or disproves it, and task 1 requires the honest
outcome to be recorded either way.

**Why this plan is last.** Every fixture key is a SHA256 over the prompt text. Plan 24-07 changed
`SYMBOL_GALLERY_PROMPT` and the semantic schema. Authoring these fixtures before that landed
would mean authoring them twice, and the failure would be a loud `KeyError` on every one.

Output: two authored fixture sets with recorded provenance, and a two-variant differential gate
that runs free.
</objective>

The gate, in one sentence: run the pipeline twice over the same PDF with the same geometry,
once with the variant A analyzer and once with the variant B analyzer, and assert the published
item set is equal.

Assert exactly these, and nothing broader:

- the SET of `(name, unit, quantity, measure_basis)` tuples from the calculated take-off;
- the SET of item names from the take-off summary;
- the SET of candidate IDs in the unnamed-geometry ledger — a candidate must not be named in one
  variant and ledgered in the other, which is the same defect wearing a different hat.

**Do not compare whole JSON blobs.** They carry timestamps, paths and run directories and would
fail for reasons that have nothing to do with determinism, producing an unmaintainable gate.

**Do not assert a golden total.** Rule 2 of the phase-23 acceptance module forbids it and this
module inherits it. The assertion is set equality BETWEEN THE TWO VARIANTS, never equality
against a golden figure. If both variants are wrong in the same way, this gate correctly passes
— it measures determinism, not accuracy, and conflating the two is what the phase exists to
separate.

Add `test_missing_fixture_skips_and_never_passes`: point the analyzer at an empty directory and
assert the harness SKIPS with a named reason rather than passing. Keep `ReplayAnalyzer`'s
`KeyError` behaviour intact — catch it at the test level and convert to a skip, so a prompt
drift is still loud but a fresh checkout without fixtures does not report a false green.

`test_four_set_coverage.py:86`.

**The whole module must run free.** No paid pytest marker, no paid script name, no credential,
