<objective>
Build the ONE new deterministic primitive this phase needs: "the words nearest to this
candidate's bbox, excluding masked regions, ranked by distance" — and attach an anchor
record to every candidate in the deterministic bundle, before any vision call.

Purpose: the Set-of-Mark marker chip currently carries only the candidate ID
(`overlay.py:110`, `label = candidate_id`). That is precisely the *symbol-conveyed*
condition the evidence base measures at 0.03-0.39 accuracy, against 0.65-0.92 for
text-anchored classes. Every ingredient for an anchor already exists in this codebase
(`contained_texts`, `page.get_text("words")`, `tag_pairing.pair_two_token_tags`,
`tag_pairing.sheet_mask_rects`); only the "nearest words to bbox" query is missing.
This plan computes anchors. Plan 24-07 delivers them to the model. Plan 24-04 uses their
absence as the flag.

**A measured finding this plan is built on (resolved FREE this session, 24-RESEARCH Open
Question #4 — answer: NO).** A zero-API deterministic-bundle probe over all four Crow
sheets returns 107 symbol groups. Of those:

| population | count | what happens today |
|---|---|---|
| no `contained_texts` at all | **81** | `fusion.py:1255` names them `SYM-*` — a raw ID published as a line item |
| `contained_texts` present but 100% drafting noise | **26** | dropped by `_is_noise_cluster` |
| `contained_texts` carrying a genuine object name | **0** | — |

The 56-EA bollard candidate is Crow page 0 `SYM-2` (0.8 x 0.87 ft) and it has **zero**
contained text. The 136 candidate is page 0 `SYM-1` (1.0 x 0.4 ft), also zero.

The consequence is load-bearing and must not be softened: **the `contained_texts` branch
of the anchor precedence yields nothing at all on the mission's primary plan set.** The
research assumed `contained_texts` would be the preferred distance-0 source; measurement
says it contributes zero anchors on Crow. Therefore the nearest-non-masked-word query is
not an enhancement to the anchor ladder — it IS the anchor ladder. Implement the full
precedence anyway (it is free and correct on other sheet sets), but size and test the
radius query as the mechanism that actually has to work.

Output: `deterministic/text_anchor.py`, its test module, and a new `candidate_anchors`
key on the deterministic bundle.
</objective>

  <behavior>
    - `nearest_anchor(bbox_pt, words, mask_rects, radius_pt)` with a word whose box is inside `bbox_pt` returns that word, `anchor_kind="contained"`, `anchor_dist_pt == 0.0`.
    - A word lying inside any rect of `mask_rects` is never returned, even when it is the geometrically nearest.
    - With no word inside `radius_pt`, the return is an anchor record whose `anchor_text` is None and whose `anchor_kind` is None — an absence, never a substitute.
    - Two words at equal distance resolve to the same one on every call (tie broken by document order), so repeated invocation is byte-identical.
    - A two-token tag paired by `pair_two_token_tags` (e.g. a prefix beside a number) is returned as ONE anchor with `anchor_kind="tag"` and `anchor_source="tag_pairing"`, not as two separate words.
    - When one word is the nearest anchor for two different candidates, both candidates come back unanchored with an ambiguity reason recorded — the word is never handed to whichever candidate was scanned first.
    - Anchor records are plain dicts (JSON-serialisable) so they survive into the bundle and into a fixture.
  </behavior>
  <action>
Create `src/bobbytailor/deterministic/text_anchor.py`.

Module docstring states why a NEW module rather than growing `tag_pairing.py`: `tag_pairing`
answers "which two printed tokens form one tag"; this module answers "which printed text is
nearest to this geometry". Different questions, different inputs. 24-RESEARCH section 10
challenges new modules and section 2.2 sanctions exactly this one.

Public surface:

- `ANCHOR_RADIUS_PT` module constant. Choose it from PAGE GEOMETRY reasoning and state that
  reasoning in the comment (a callout leader on an architectural sheet is a small multiple
  of the text height). Under no circumstances select this value by running a take-off and
  watching an accuracy score move — that is 24-RESEARCH pitfall 1 and it is forbidden. The
  validation for this constant is positional: the word chosen must be the geometrically
  nearest non-masked word, provable by hand on a real page.
- `anchor_record(candidate_id, text, kind, dist_pt, source, ambiguity_reason="")` -> dict with
  keys `candidate_id`, `anchor_text`, `anchor_kind`, `anchor_dist_pt`, `anchor_source`,
  `ambiguity_reason`. This is the contract from 24-RESEARCH section 2.3.
- `page_words(page)` -> list of `(x0, y0, x1, y1, text)` via `page.get_text("words")`, filtered
  to non-empty text. Mirror `symbols.py:494` rather than inventing a second harvest shape.
- `nearest_anchor(bbox_pt, words, mask_rects, radius_pt=ANCHOR_RADIUS_PT, tag_pairs=())` ->
  anchor record. Precedence, in order: contained (word box centre inside `bbox_pt`, distance
  0.0, kind `contained`) -> a `tag_pairs` union-box within radius (kind `tag`, source
  `tag_pairing`) -> nearest single word within radius (kind `nearest_word`, source
  `page_words`) -> None-anchor. Distance is edge-to-edge box distance, 0.0 on overlap.
- `anchors_for_candidates(page, candidates, mask_rects=(), radius_pt=ANCHOR_RADIUS_PT)` ->
  `{candidate_id: anchor_record}`. `candidates` is `{candidate_id: bbox_pt}`. Internally:
  harvest words once, drop masked words once, build `tag_pairs` once via
  `tag_pairing.page_tag_lines` + `tag_pairing.pair_two_token_tags`, then resolve each
  candidate. Sort candidate iteration by candidate ID so the scan order is fixed.
- Ambiguity: after a first pass, any anchor text claimed by more than one candidate is
  WITHDRAWN from all of its claimants, each of which is re-emitted as a None-anchor whose
  `ambiguity_reason` names the contested text and the competing candidate IDs. This is
  SP-7c `bind_or_flag` semantics: bind only when exactly one candidate and exactly one
  surviving text remain. Never round-robin.

**Do NOT filter anchor candidates through `fusion._is_noise_token`.** That predicate answers
a different question (is this cluster's own contained text an object name?) and it returns
True for exactly the tags an anchor needs: a hyphenated letter-digit bollard tag matches
`_SHEET_ID_RE`, and a short letter-digit paint tag matches `_GRID_LABEL_RE`. Reusing it here
would reject the anchors this requirement exists to harvest. Anchor harvesting is
unfiltered; deciding whether an anchored name is publishable belongs to plan 24-04.

Every public function is pure over its inputs plus the `fitz.Page` text layer. No API, no
network, no environment read.

Write `tests/test_text_anchor.py` covering each bullet of the behavior block, using
synthetic word lists for the unit cases (no PDF needed) so the module's contract is provable
without a fixture.
