<objective>
Kill the naming-library variance at its root: fold the name FORM so one object cannot occupy
two rows, and declare ONE naming-authority precedence that every publication path obeys.

Purpose: this is the largest single variance source measured across the two saved paid runs,
and both V4-DET-02 and V4-DET-04 depend on it. The smoking gun is one candidate:

| run | published name | `source` field |
|---|---|---|
| 14:19 | `Bollard` | `learned` |
| 18:13 | `Dock Bumper` | `library` |
| both | `Bollards` (blank row) | `expected_not_measured` |

Three naming authorities race with no arbiter — the learned store, the component library plus
project vocabulary, and the vision label kept verbatim. And the split survives because
`_norm_item_key` (aggregator.py:80-82) collapses separators and case but NOT plurals, so
`bollard` and `bollards` are two different bucket identities. A client reading that report
sees a measured `Dock Bumper` beside a blank `Bollards` and concludes bollards were not found.
That is strictly worse than either row alone.

**The boundary that must not be crossed.** `canonical_library_name`'s docstring
(aggregator.py:292-306) is explicit that it normalises the FORM of one item's name and never
renames one item to another. That is the right call. Plural folding is a form transformation
of the same class as the spacing and case folding already performed, and is in-boundary. A
synonym or fuzzy matcher is a RENAME and is out-of-boundary — it is how `Dock Bumper` would
silently become `Bollards`, which is a worse defect than the split it would appear to fix.
24-RESEARCH pitfall 5. The negative test is mandatory, not optional.

**Scope note.** This plan does not stabilise the CONTENTS of the derived vocabulary — that is
plan 24-05, which persists it per project. This plan stabilises the FORM and the ARBITER. Both
are required before V4-DET-02 holds end to end.

Output: plural-aware canonicalisation, one precedence helper, a reconciliation rule for the
expected-versus-measured pair, and four named tests including the negative.
</objective>
