24-RESEARCH section 7.2 attributes defect F9 — `raw_line_items` swinging 184 to 64 between the
two saved runs — to `_run_pass` being single-shot, and assumption A1 records the risk that it
was budget truncation instead, with the mitigation "verify by comparing run 2's truncation
record against the missing rows before committing". That comparison was performed FREE during
planning, directly from the two saved artifacts:

| | run 1 (14:19) | run 2 (18:13) |
|---|---|---|
| `budget.cap_usd` | **1.50** | **0.60** |
| `budget.spent_usd` | 0.824540 (55% of cap) | **0.598807 (99.8% of cap)** |
| `api_usage.total_cost_usd` (sheet-attributed) | 0.3826 | **0.1766** |
| implied project-level spend | 0.4419 | 0.4222 |
| `models_used` | opus x1 + sonnet x2 | opus x1 only |
| `raw_line_items` | 184 | 64 |

Run 2 ran under a budget cap **2.5 times smaller**, reached **99.8% of it**, spent **less than
half** as much on sheet-level work, and invoked one model class where run 1 invoked three. The
184-to-64 swing is overwhelmingly explained by budget, not by single-shot nondeterminism. A1's
stated risk is the actual situation.

**Two consequences the executor must carry:**

1. **Do not justify this plan by F9.** F9 is confounded. The honest justification is the one
   V4-DET-04 states on its own: `_run_pass` is the one un-ensembled identification path in
   plans-only mode, and an un-voted identification pass can flip. That is true regardless of
   what caused F9, and it is sufficient.
2. **Tripling schedule and legend spend on a run that already hit 99.8% of its cap would make
   the artifact WORSE, not better.** The cost pairing with plan 24-05 is therefore load-bearing,
   not a nicety: 24-05 removes roughly 70% of a repeat run's spend (the project-level passes
   were $0.422 of run 2's $0.599), and that is what this fan-out is allowed to consume. The
   voting must be budget-aware and must degrade to today's behaviour rather than starving the
   sheet passes.

Also record, rather than silently skipping: the second un-voted call site at
takeoff_pipeline.py:4903 is the manifest-gated tiled count path. The mission is plans-only, so
it is deliberately out of scope. 24-RESEARCH section 7.3.3 asks for the decision to be recorded.

**And do not add a temperature parameter as a remedy.** Hosted-API nondeterminism comes from
batch-size-dependent GPU reduction kernels, not from sampling; `temperature=0` cannot fix it.
This codebase already has `_probe_temperature_ignored` (ensemble.py:402) acknowledging exactly
that.
