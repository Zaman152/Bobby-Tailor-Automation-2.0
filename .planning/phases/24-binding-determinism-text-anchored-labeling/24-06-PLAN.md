<objective>
Make the unnamed-geometry ledger visible. Plan 24-04 stopped identifier rows publishing as line
items and recorded every excluded candidate with its evidence; this plan puts that record in
front of a human, in both artifacts a client actually reads.

Purpose: a silently-omitted high-count cluster reads as "there are no columns." That is the
mirror-image defect of publishing the identifier, and 24-RESEARCH pitfall 3 names it explicitly:
deletion is the shortest path to "no identifiers in the report" and it silently loses hundreds
of counted symbols. Phase 23's INV-08 established the same rule one level up — a deletion and a
zero read identically to a client. So the ledger is mandatory, not optional, and it must appear
as a NAMED section stating what it is: candidates that were measured but not identified.

This plan also resolves **24-RESEARCH Open Question 1** (was the ensemble N 3 or 1 on the saved
runs?). Neither saved `takeoff.json` records the effective N, the environment file is off
limits, and so the question is permanently unanswerable for those runs. It need never be
unanswerable again: `RunSettings.to_dict()` already exists (takeoff_pipeline.py:224) and already
carries `ensemble_n` and `budget_usd` from the single `ensemble_settings()` reader. Emitting it
into the report is a one-key change with permanent diagnostic value.

**Note on file ownership.** `reporter.py` is also touched by plan 24-05 in the previous wave.
This plan runs after it; take the file as it stands rather than reverting anything.

Output: two additive report keys, a summary.txt section and an Excel worksheet — none of which
appear at all when the run carried no unnamed geometry.
</objective>
