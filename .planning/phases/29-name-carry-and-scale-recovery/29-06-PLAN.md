<objective>
Give the pipeline a second pass that reasons over the assembled ledger, so a quantity the
drawing DEFINES BY RULE rather than by drawing can be computed — or, far more often, so its
blank can finally say what it is waiting for.

Purpose: the engine measures what is drawn and reads what is tabulated, and has no route at all
for what is SPECIFIED. "Provide X at all Y" is how a large fraction of a real take-off is
communicated, and today every one of those items is an opaque blank.

Expectation, stated before the work so it cannot be claimed afterwards: **this will probably NOT
produce Crow's Bollards = 28.** Note 13 is compound and a jamb is not a door. What it should
produce is a Bollards blank whose reason names note 13, names the drive-in door count the run
does have, and names the riser count it does not — an estimator closes that in 30 seconds
instead of wondering why the cell is empty.
</objective>

<tasks>

## T-29-06-01 — The rule reader

Match only EXPLICIT quantity rules over a small, stated pattern set:
`PROVIDE <X> AT (ALL|EACH) <Y>` · `<X> AT (ALL|EACH) <Y>` · `(ONE|TWO|\d+) <X> (PER|AT EACH) <Y>`.

Return a structured `QuantityRule(subject, referent, factor, factor_stated: bool, note_text,
sheet)`. Anything not matching returns nothing — this reader guesses at nothing and there is no
fallback branch.

## T-29-06-02 — Compound refusal, first and loudest

A referent clause containing a comma or ` AND ` binds MORE THAN ONE referent. Refuse it: emit a
rule marked `compound=True` carrying every referent phrase it found. Compound rules never
produce a number. Crow note 13 is the fixture for this and the test asserts the refusal by name.

## T-29-06-03 — The resolver, over assembled buckets

For a single-referent rule, find the ONE bucket whose name or alias set matches the referent. If
zero match, or MORE THAN ONE matches, refuse — 29-02 measured the cost of arbitrating an
ambiguous bind (136 personnel doors published as galvanized frames because the tie broke on name
length). One match, with a real quantity, produces `subject = referent_qty * factor`.

## T-29-06-04 — Publish flagged, or blank with the rule quoted

Derived row: `needs_review=True`, quantity set, review reason quoting the note verbatim, naming
the referent bucket and its quantity, and stating whether the factor was printed or assumed.
Refused rule: a BLANK row under a new `_UNMEASURED_SOURCES` marker, reason quoting the note and
naming precisely what blocked it (compound / referent not counted / ambiguous referent).

## T-29-06-05 — Tests

- Crow note 13 → parsed, `compound=True`, NO quantity, blank reason names both referents.
- Synthetic single-referent rule over a real bucket → resolves, flagged, factor recorded.
- Rule whose referent nothing counted → blank naming the referent.
- Rule matching two buckets → refused, both named.
- No note matching the patterns → the module emits nothing and the take-off is byte-identical.
- Four-set sweep: report how many rules the reader matches per plan set, committed as a pin.
- NON-VACUITY: every assertion proved red before being kept.

</tasks>

<limits>
- Reads ONLY notes text already harvested and buckets already aggregated. No new extraction, no API.
- Does NOT attempt jamb-per-door, riser counting, or any domain multiplier the drawing does not print.
- A derived quantity NEVER publishes MEASURED and never counts toward coverage as a measurement.
- If the four-set sweep shows the reader matching notes that are not quantity rules, the patterns
  narrow — the reader must be quiet on three sets rather than noisy on all four.
</limits>
