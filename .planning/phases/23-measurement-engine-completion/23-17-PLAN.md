<objective>
Surface the coverage ledger everywhere a client actually reads numbers.

Purpose: plan 23-01 builds the ledger and plan 23-03 makes every silent drop write into it, but until
this plan lands the record exists only in memory. The honest bookkeeping problem this phase exists to
fix is not "we did not know" — it is "we knew and no artifact said so". Today the report is a complete
account of what WAS found and a total silence about what was not (INV-08 §2 closing note).

The provenance classification must also MOVE into the package. Today the workbook exporter INFERS
provenance from the value, which has three consequences: a genuinely measured zero is
indistinguishable from a never-attempted measurement; an item that produced no row at all cannot be
labelled at all, and absence is precisely the defect; and only spreadsheet users ever see it, while
the JSON, the CSV, the web view and the API all ship the bare number (INV-08 §5).

Scope note: this plan was split out of 23-03 so that neither exceeds its context budget. Every wave
from 3 onward depends transitively on 23-03, so that plan carries only the pipeline-side contract and
this one carries the report-side surfacing. The two run in the same wave and share no file.

Output: the four additive report fields, `coverage.json`, the `summary.txt` COVERAGE section, the CSV
provenance column, and the workbook Coverage worksheet.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| run report JSON → web UI, CSV, Excel, scoring | New fields and a changed quantity type reach every downstream consumer |
| ledger text → rendered report | Untrusted drawing text becomes report and workbook content |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-23-70 | Tampering | A new report field breaks an existing consumer | high | mitigate | Every field is additive, no key is renamed, and a no-ledger report is asserted byte-identical to the pre-change output |
| T-23-71 | Denial of Service | `coverage_ledger` inflates `takeoff.json`, which the web UI loads whole | medium | mitigate | Drawing rows stay flat — no bitmaps, no region lists; roughly 240 rows on a 40-page set, negligible beside raw line items |
| T-23-72 | Information Disclosure | Classifier context and drop reasons embed raw drawing text into an exported workbook | low | accept | The text is drawing content the report already renders; reasons are short and bounded |
| T-23-73 | Repudiation | Provenance is inferred rather than recorded, so a measured zero and a never-measured item look alike | high | mitigate | Classification moves into the package and is computed from the record; pinned by the measured-zero rendering test |
| T-23-74 | Spoofing | An empty CSV cell is read downstream as a zero | high | mitigate | The offline scorer's existing coercion maps an empty cell to nothing, asserted end to end rather than assumed |
</threat_model>
