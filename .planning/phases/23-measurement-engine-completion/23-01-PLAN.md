<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| uploaded PDF → parser | Fully untrusted binary; page count, text and drawing streams are attacker-controlled |
| run report JSON → downstream consumers | New/changed fields are read by the web UI, CSV export and scoring scripts |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-23-01 | Denial of Service | `run_pdf_analysis` per-page `measurable_signal` computation | medium | mitigate | Signal computation is bounded per page and wrapped so a malformed page records `disposition=ERRORED` with the message instead of aborting the run |
| T-23-02 | Denial of Service | `CoverageLedger` growth on a huge PDF | low | mitigate | `DrawingCoverage` stays flat — no bitmaps, no region lists (INV-08 risk 3); one row per page bounds the ledger at `doc.page_count` |
| T-23-03 | Information Disclosure | `classifier_context` embeds raw page text into the report | low | mitigate | Context is capped at ~50 characters around the match; it is drawing text the report already renders elsewhere |
| T-23-04 | Tampering | Skip veto widens which pages run code paths | medium | mitigate | Veto routes to the deterministic path only — no model call, no network, no spend; pinned by the zero-API acceptance test |
| T-23-05 | Repudiation | A skipped page leaves no auditable record | high | mitigate | Every skip records keyword, context and measurable signal on its ledger row; `assert_accounted()` proves no page is missing |
</threat_model>
