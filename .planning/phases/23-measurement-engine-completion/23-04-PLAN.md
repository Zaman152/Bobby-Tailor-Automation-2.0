    Add a text normaliser that uppercases, collapses dotted initialisms of two or more single-letter
    groups into one token, and reduces remaining non-alphanumerics to single spaces — so the split
    frame cells, the hyphenated steel form, the solid-core form and the aluminium abbreviation all
    become readable.

    Add a material-code resolver driven by a module-level list of phrase-to-code pairs, returning the
    LEFTMOST then LONGEST match and the empty string when nothing matches. Leftmost is load-bearing:
    a solid-core wood leaf with a glass lite must resolve to the leaf material, and an aluminium door
    with insulated glazing must resolve to aluminium. Canonical codes are HM, SCW, WD, HC, ALUM,
    GALV, GLASS, STL, KD, FRP and IM. This resolver replaces every bare-token membership test in the
    module.

    Add a column-role detector that joins the first four rows per column — schedules stack two or
    three header rows — normalises them, and assigns the first matching role among count, frame
    material, panel material and tag. Roles are advisory; content detection fills the gaps.

    Modify the material-column scorer to evaluate each cell AND that cell joined with its right
    neighbour, and to run PER MISSING ROLE rather than only when both roles are missing — Bob's finds
    its panel column from a header but its frame header is split across two cells, so the frame
    column must still come from content.

    Add a count-column resolver: the header role first, else a column within three of the tag column
    that is at least sixty percent small integers. Returning nothing is a VALID and expected answer
    meaning one door per row — that fallback is what makes Bob's and Moxy readable at all.

    Mitigate the merged-header fragment case (INV-07 risk 6): when a table shares a title band with a
    sibling table that DID yield roles, inherit the sibling's column roles by index, so the guestroom
    fragment stops reading its frame column as its panel column.
