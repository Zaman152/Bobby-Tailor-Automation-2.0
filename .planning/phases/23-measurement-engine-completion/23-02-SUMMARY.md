# Phase 23 Plan 02: Printed-Scale Parser Hardening (SP-2) Summary

**Bob's callouts now parse to their real ratio — the paper-inch measure is read from the token the
inch mark belongs to instead of the first digit run on the line — correcting exactly 7 of 390
printed scales across four drafting offices and moving none of the other 383.**

## Performance

- **Duration:** ~2h
- **Tasks:** 3 of 3
- **Files modified:** 3 (+2 created)

## What shipped

**The anchored parse (`_paper_inches`).** The old scan took the FIRST digit run anywhere left of
`=`. On `'2 SCALE: 18" = 1'-0" FRONT ELEVATION NEW'` that is the drawing number `2`, so the sheet
resolved 0.5 ft/in instead of 8.0 — 16x linear, 256x by area, on every quantity of the drawing.
The parse now anchors on the last inch mark before `=` and reads **leftward** from it, trying in
order: mixed number, plain fraction, split stacked fraction, concatenated stacked fraction, literal
measure. The anchor is not a heuristic — the paper-inch measure is by construction the token the
inch mark belongs to.

**The split stacked fraction (BUG-A).** `_DROPPED_SLASH_FRACTIONS` keyed only on the concatenated
form (`"332"`), but `rawdict` shows Bob's A3.0 emits the ratio as three spans with the stacked glyph
flattened to `'3 32'` — a SPACE where the slash was, not a concatenation. Two new rules: when the
concatenation is a standard-fraction key, `"3 32"` is 3/32; otherwise when only the second token is
a key, `"1 12"` is 1 + 1/2. Concatenation is tried first because `'1 16'` is 1/16 on Bob's, not
1 + 1/6 — the ordering is load-bearing and both directions are pinned. The module docstring now
records the rawdict evidence.

**Leading drawing-number recovery (`_number_and_title`).** The left-side digit strip deletes every
digit run — it cannot tell a leading drawing number from the paper-inch measure it exists to remove
— so Bob's, which prints the number first, lost it. The fallback takes a leading LONE integer
(digits, whitespace, then a non-numeric character), which no leading measure can satisfy: a measure
is always followed by a digit, `/`, `.` or an inch mark. It runs **after** the title is built, so
"no title may move" is structural rather than something to re-check.

**The pin (`tests/fixtures/printed_scale_pre_sp2.json`).** The four-fixture diff was a one-off
observation in INV-03 §4.1; it is now a committed regression. The fixture freezes the pre-SP-2 parse
of all 410 callouts (390 parseable) across Moxy/Crow/Bob's/Chelsea. It is captured from the OLD
parser and must never be regenerated from the current one — that would make the pin tautological,
and the fixture's own `_README` field says so.

**The probe.** `scale_probe.py` gained argparse, multi-PDF input and `--json` (per-page callout
texts with parsed fpi, distinct fpi, resolved main scale, per-viewport scale). The human-readable
report is deliberately unchanged byte-for-byte — it is the surface the four-fixture diff is eyeballed
on, so the new detail went into `--json` instead.

## Deviations from Plan

### 1. [Rule 3 — blocking] The `--json` detail could not go in the human report

- **Found during:** Task 3.
- **Conflict:** the action asks the probe to "emit, per page, the printed-scale texts with their
  parsed feet-per-inch … keeping the current human-readable output shape", while the acceptance
  criterion requires the three-fixture run to be **byte-identical** to the pre-change run. Adding
  per-callout lines to the report violates the second.
- **Resolved as:** the human report is frozen byte-for-byte and the new per-callout detail is
  carried by `--json` (plus a reusable `probe_pages()` for callers). Byte-identity was then verified
  three ways — each fixture individually, and the combined 3-arg invocation the criterion names.
- **Commit:** `933e691`

### 2. [Rule 2 — missing critical functionality] The pin needed a frozen "before", and a decay guard

- **Found during:** Task 3.
- **Issue:** the plan says to assert `changed=7 unchanged=383`, but a test can only compute
  "changed" against a recorded prior value. Deriving that from the current parser would make the pin
  assert `x == x`.
- **Fix:** the pre-SP-2 parse was captured **before** any edit and committed as
  `tests/fixtures/printed_scale_pre_sp2.json`. Added `test_pre_sp2_fixture_matches_todays_block_extraction`
  so the pin fails loudly if block extraction or `_looks_like_scale_label` later changes and the
  fixture starts pinning callouts the parser no longer sees.
- **Also added (not requested):** two negative controls were executed and recorded, because a pin
  nobody has seen fail is not known to work.
- **Commit:** `933e691`

### 3. [Rule 2] `_paper_inches_unanchored` extracted rather than deleted

- **Found during:** Task 1.
- **Issue:** the plan requires "when the left-hand text contains no `SCALE` keyword — Moxy's bare
  ratios — keep today's behaviour unchanged". Re-expressing that with the new patterns would be a
  rewrite claiming to be a no-op across 40 Moxy sheets.
- **Fix:** the legacy scan is lifted verbatim into `_paper_inches_unanchored` and called on that
  branch, so bare ratios take a literally unchanged code path. Pinned by
  `test_bare_ratio_without_scale_keyword_takes_the_legacy_path`.
- **Commit:** `d3fde23`

### 4. [Rule 2] T-23-06 mitigated with bounded quantifiers

- The threat register requires the patterns stay linear-time. The anchored patterns use `{1,4}`
  rather than `+`, bounding backtracking on a long digit run, with the observed justification in a
  comment (widest real measure is 3 digits: `"132"`, `"316"`). Pinned by a timing test on a
  10,000-token adversarial callout.
- **Commit:** `d3fde23`

### 5. [Scope boundary — logged, NOT fixed] Three out-of-scope discoveries

Recorded in `.planning/phases/23-measurement-engine-completion/deferred-items.md`:

- **DEF-23-01** — `SCALE: 1-1/2" = 1'-0"` parses as 1/2 → 2.0 ft/in, not 1.5 → 0.667. Genuinely
  wrong, wrong *before* this change too, and a **different defect** from BUG-A/BUG-B. Fixing it
  moves 2 extra Bob's rows to `changed=9 unchanged=381` and breaks the pin this plan exists to
  establish — verified by running exactly that as negative control 2. Pinned as-is with the reason
  in the test docstring so the behaviour is documented rather than latent. Both callouts are on
  A8.3 STANDARD DETAILS, so nothing measured today depends on them.
- **DEF-23-02** — the offline suite rewrites three tracked `tests/fixtures/synthetic/*.pdf` on every
  run. Pre-existing, unrelated to SP-2; they were deliberately left unstaged in all four commits.
- **DEF-23-03** — `main=None` on Bob's pages 3 and 4 is BUG-C (rotation-unaware callout binding),
  owned by plan 23-07 and explicitly forbidden here. Logged so the probe output is not misread as an
  SP-2 defect; it is present identically before the change.

## Issues Encountered

**One test was written wrong and caught it.** `test_a_leading_measure_is_never_read_as_a_drawing_number`
initially included `'1. DO NOT SCALE DRAWINGS.'`, which fails — but for a pre-existing reason: the
*main* scan (unchanged by this plan) reads `1.` as a drawing number, and the string never becomes a
`PrintedScale` anyway because it has no `=`. The row was conflating pre-existing behaviour with the
new fallback and was replaced with genuine leading-measure forms.

## Threat Flags

None — no new security-relevant surface. The plan's three registered threats:

- **T-23-06 (DoS on adversarial callout text)** — mitigated: bounded `{1,4}` quantifiers, no nested

- **T-23-07 (a mis-parsed scale silently corrupts every measurement)** — mitigated: the seven

  seven *different* movements also sum to seven. Validation is against each drawing's own printed
  ratio, never a golden quantity.
- **T-23-08 (a crafted callout claims an implausible scale)** — accepted, as registered; the
  datum-band plausibility check lands in 23-14.
