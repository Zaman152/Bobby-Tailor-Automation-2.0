<objective>
Record, on every counted row, whether anything corroborated the count — and mark the specific
uncorroborated case that produced this phase's worst defect: an install count read off a sheet the
run itself classified `detail`.

Purpose: `Stairs` published `MEASURED`, `needs_review=False`, confidence medium, at **1.00 in run A
and 2.00 in run B**. Its `source_location` reads *"Detail 10 (Stair Section), Detail 8 (Stair Rail),
Detail 6 (Stair Plan), Detail 9 (Z-Grade Detail)"* in run A and *"Detail 10 (Stair Section) and
Detail 6 (Stair Plan)"* in run B. The model was counting **stair details on A-401**, and the number
moved because the number of details it noticed moved. The codebase already refuses exactly this —
`_calculate_from_measurement` drops `bollard/stairs/columns/ladder/lift/...` on a `detail` sheet
(RC-6, widened by 23-15) — but the guard was never given to `_calculate_from_component`, and the
count path is the path `Stairs`, `Lift` and `Door Frames-HM` all travelled.

This plan writes the verdict. It does NOT change a single published status or quantity; 28-03 owns
the publish decision. Splitting it that way is what keeps this plan's blast radius to one function
and one file.

Output: a `count_corroboration` verdict on every count row, a shared item-type constant, and a test
module that pins the verdict against the two saved paid runs' own recorded fields.
</objective>
