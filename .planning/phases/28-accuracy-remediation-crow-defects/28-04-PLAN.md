<objective>
Stop a non-unique printed-thickness match from outranking a vision reading that contradicts it.

Purpose: `CMU Wall` published **11,286 SF** against golden 2,204 — 412% high, deterministic
provenance, **bit-identical in both paid runs**. This is a reproducible binding error, not noise.
The audit trail already says exactly what happened:

> the naming library object `CMU Wall` prints a 8.0" thickness and this wall class measures 8.0"
> (LF-weighted mean), within the 1.5" match tolerance; a printed-thickness match is deterministic
> evidence and outranks a vision reading, so the reading `tilt-up concrete panel` did not name this
> class

Two things are wrong with that sentence, and only the second one is about CMU.

**Thickness is not identity when it is not unique.** Crow's sheet prints S.C.C.P. site-cast tilt
panels throughout — the naming prompt's own extract carries `TYPICAL S.C.C.P. JOINT DETAIL`,
`ALL SITE CAST CONCRETE PANEL WIDTHS...`, `ALL TILT WALL PANELS SHALL BE CAULKED...` — and it prints
one masonry room. Tilt panels and CMU commonly print the same nominal thickness. A match that two
objects satisfy discriminates between them not at all, and calling it "deterministic evidence" is
the error.

**And the guard that was supposed to catch this only looked at one class.** A masonry object may not
bind the *dominant* class. Crow has thirteen wall thickness classes; the one that took `CMU Wall`
carries roughly 313 LF at the published height, which is a large share of the sheet but not the
largest, so the guard never fired.

Fix the class selection. The number is downstream of it. Do not filter wall classes until the SF
lands near 2,204 — that is the documented, rejected methodology.

Output: a bind that refuses when its evidence does not discriminate, and an audit record that says
so.
</objective>
